# Shipay 航空机票交易服务 App 正式需求说明书

## 1. 文档目的
本说明书用于定义 Shipay 航空机票交易服务 App 的正式需求，确保产品、设计、研发、测试与运营团队对产品目标、范围、功能及交付标准形成统一理解，并作为项目规划、开发实施、验收测试与后续迭代的依据。

## 2. 背景与目标
- **业务背景**：随着自由行、商旅出行需求增长，用户希望在移动端快速完成机票选购、支付及售后服务。现有旧版需求无法满足迭代开发的准确性，需形成正式版需求文档。
- **产品目标**：提供安全、快捷、透明的机票搜索与交易服务，满足消费者、旅行代理人与航空公司三方需求，提升购买体验与交易效率。
- **成功指标**：
  - App 首次上线 3 个月内注册用户 ≥ 50,000。
  - 日活跃用户（DAU）≥ 5,000。
  - 下单转化率 ≥ 8%，支付成功率 ≥ 98%。
  - 客服投诉率 ≤ 0.5%。

## 3. 项目范围
- **在范围内**：机票搜索、比价、预订、支付、订单管理、售后服务、会员体系、优惠活动、客服、数据统计、系统管理后台。
- **不在范围内**：酒店/租车等非机票产品、线下出票系统改造、航空公司内部结算系统等。

## 4. 用户与角色
| 角色 | 描述 | 核心需求 |
| --- | --- | --- |
| 终端消费者 | 个人旅行者或企业员工 | 搜索航班、比价预订、便捷支付、查看行程与退改签 |
| 旅行代理 | 代客预订人员 | 批量下单、管理客户订单、查看结算报表 |
| 航空公司运营 | 航空公司合作方 | 发布航班及库存、查看销售数据 |
| 平台客服 | Shipay 内部客服 | 处理售后、投诉与异常订单 |
| 系统管理员 | 平台运营人员 | 管理账号权限、配置资源、监控系统 |

## 5. 用户旅程概览
1. 终端消费者下载并注册登录 App。
2. 搜索航班，筛选符合时间、价格、航空公司的航班。
3. 查看航班详情，选择座位或票种。
4. 填写乘机人信息，选择附加服务与优惠。
5. 选择支付方式并完成支付。
6. 支付成功后获取电子行程单，订单进入“待出行”。
7. 若需改签/退票，通过 App 售后入口发起申请并跟踪进度。

## 6. 功能需求
### 6.1 用户账号与安全
- 支持手机号、邮箱注册，需短信验证码或邮件验证。
- 支持微信/支付宝/Apple/Google 单点登录。
- 支持多因素认证（MFA），敏感操作需二次验证。
- 支持账号信息维护（昵称、证件、联系人、密码）。
- 支持账号安全通知、登录设备管理与异常提醒。

### 6.2 航班搜索与浏览
- 输入出发地、目的地、出发日期、乘客类型进行搜索。
- 提供日期日历视图、最低价日历。
- 支持筛选条件：起飞时间段、航空公司、舱位、经停、价格区间、退改签规则、行李额度。
- 支持排序：价格、出发时间、到达时间、耗时、推荐。
- 展示航班列表与航班详情（包含航班号、机型、准点率、舱位库存、退改签规则、费用组成）。

### 6.3 订单预订流程
- 乘机人管理：支持新增成人/儿童/婴儿乘机人信息，自动校验证件有效期。
- 附加服务：选购行李额、选座、餐食、保险、会员积分兑换。
- 费用明细实时计算（票价、税费、服务费、保险费、优惠券/积分抵扣）。
- 确认订单前提供订单核对页，展示票规与退改签条款。
- 支持保存订单草稿 30 分钟，过期自动释放库存。

### 6.4 支付与结算
- 支持支付方式：微信支付、支付宝、银联云闪付、信用卡、企业月结。
- 接入第三方支付渠道，符合 PCI-DSS 标准。
- 支付成功/失败实时通知，记录交易流水。
- 订单支付超时自动取消并恢复库存。
- 对账管理：每日生成支付对账报表，供财务下载。

### 6.5 订单管理
- 我的订单：按照状态分类（待支付、已支付、待出行、已出行、退款中、已退款）。
- 订单详情：航班信息、乘机人、费用明细、电子票号、附加服务。
- 支持导出行程单、发送邮件、下载 PDF。
- 支持改签、退票申请，展示退改签费用计算与进度跟踪。

### 6.6 售后与客服
- 在线客服：集成 IM/机器人客服，提供 FAQ。
- 工单系统：记录用户提交的售后问题，支持客服分配、优先级设置。
- 通知中心：推送订单状态变更、航班延误/取消通知、售后结果。
- 投诉处理：记录投诉类型、处理进度、反馈结果。

### 6.7 会员与营销
- 会员等级：根据累计消费与积分划分等级，享受专属权益。
- 积分体系：订单支付返积分，支持积分抵扣。
- 优惠券：发放满减券、折扣券、立减券，支持用户领取与使用规则控制。
- 营销活动：秒杀、限时折扣、拼团等活动管理。
- 消息推送：支持个性化营销推送，遵循用户隐私偏好。

### 6.8 数据与统计
- 数据仪表盘：展示交易额、订单量、客单价、转化率、售后率等指标。
- 用户分析：新增/活跃用户、留存率、渠道来源。
- 航班分析：热门航线、航司表现、库存利用率。
- 日志审计：记录关键操作日志供安全审计。

### 6.9 管理后台
- 账号权限管理：RBAC 模型，支持角色定义、权限分配、操作日志。
- 航班与库存管理：导入航司数据、配置票价与库存、发布上下架。
- 内容管理：公告、帮助中心、广告位配置。
- 支付对账与财务结算管理。
- 系统设置：参数配置、开关控制、限流策略。

## 7. 非功能需求
### 7.1 性能要求
- 支持高峰同时在线用户 10,000，订单创建峰值 300 笔/分钟。
- 核心接口平均响应时间 ≤ 800ms，P99 ≤ 2s。
- 搜索结果返回时间 ≤ 3s。

### 7.2 安全与合规
- 符合 GDPR/CCPA、中华人民共和国个人信息保护法等隐私法规。
- 采用 HTTPS，全链路加密；敏感数据脱敏存储。
- 支持风控：异常登录检测、交易风控规则、黑名单库。
- 保证支付链路满足 PCI-DSS。

### 7.3 可用性与可靠性
- 系统可用性目标：99.9%。
- 支持主备容灾与多活部署，RPO ≤ 5 分钟，RTO ≤ 30 分钟。
- 提供监控报警、日志收集、故障定位机制。

### 7.4 可维护性
- 微服务架构，模块化设计，提供 API 文档与版本管理。
- 自动化测试覆盖率 ≥ 70%（单元、集成、UI）。
- CI/CD 流程：代码审核、自动化构建、灰度发布。

### 7.5 兼容性
- 客户端支持 iOS 15+/Android 8.0+。
- 兼容主流浏览器的网页版管理后台（Chrome、Edge、Safari 最新两个版本）。
- 支持多语言（简体中文、繁体中文、英文），支持多币种显示。

## 8. 数据设计概览
- **核心实体**：用户、乘机人、订单、航班、舱位库存、支付流水、积分账户、优惠券、活动、客服工单。
- **数据流转**：航司/代理导入航班 → 平台聚合 → 用户搜索 → 下单 → 支付 → 出票 → 行程服务 → 售后/结算。
- **数据存储建议**：交易数据使用关系型数据库（MySQL/PostgreSQL）；搜索与库存使用 ElasticSearch/Redis 缓存；日志与监控数据使用 ELK/Prometheus。

## 9. 外部系统与接口
| 系统 | 对接内容 | 协议 | 备注 |
| --- | --- | --- | --- |
| 航空公司 NDC/GDS | 实时航班与库存查询、订单创建 | REST/SOAP/XML | 支持多航司适配，需容错重试 |
| 第三方支付 | 支付下单、退款 | HTTPS API | 支持微信、支付宝、银联等 |
| 短信/邮件服务 | 验证码、通知、行程单 | HTTPS API/SMTP | 需保证送达率与退订机制 |
| 第三方保险 | 附加服务购买 | HTTPS API | 与保险公司对接保单系统 |
| 风控服务 | 反欺诈、风险评分 | HTTPS API | 提供黑名单与风控策略 |

## 10. 运营与合规要求
- 用户协议、隐私政策需在注册与首次登录时展示并征得同意。
- 提供发票申请与财务合规流程。
- 建立客服 SLA：一般工单 24 小时响应，投诉工单 4 小时响应。
- 建立数据备份策略：日备份、周全量备份、月归档。
- 定期进行安全渗透测试与合规审计。

## 11. 发布与迭代计划
- **里程碑 0**：需求评审与原型确认（2 周）。
- **里程碑 1**：基础功能开发（8 周）：账号、航班搜索、下单支付、订单管理。
- **里程碑 2**：售后、营销、数据分析（6 周）。
- **里程碑 3**：安全合规与性能优化（4 周）。
- **里程碑 4**：公测（2 周），收集反馈，修复缺陷。
- **正式上线**：版本 1.0 推出，后续每月发布一次迭代版本。

## 12. 验收标准
- 所有需求项完成并通过产品验收与回归测试。
- 功能用例覆盖率 ≥ 95%，关键路径零高优缺陷。
- 性能测试达到目标指标。
- 安全测试无高风险漏洞，合规检查通过。
- 培训完毕，运营与客服可独立使用后台。

## 13. 后续规划

- 推出企业差旅管理模块与审批流。
- 上线智能推荐与动态定价模型。
- 与酒店、租车等产品打通，形成出行生态闭环。
